feature branches. This note exists for the two workstreams that had no durable

## 1. The TMPDIR guard

`src/tmpdir.ts` — `guardTmpdir()`, `insideRoot()`, `packageRoot()`. It deletes
`process.env.TMPDIR` when it resolves inside the package root, says so once on
stderr, and throws if `TMP`/`TEMP` put it back inside rather than stripping
variables until it likes the answer. Deleting rather than replacing, because
`os.tmpdir()` already knows the platform default when the variable is unset and
inventing a path would be a second opinion about a question the platform answers.

**Called from three entry points, explicitly**: `src/cli.ts:83`,
`src/mcp/main.ts:51`, `src/server/main.ts:49`. There is no single module all
three import. `src/version.ts` misses the server; `src/index.ts` misses the CLI,
which imports deep paths and never the barrel; and `build:server` runs esbuild
WITHOUT `--bundle`, so a `scripts/*.mjs` import would survive into
`dist/server/main.js` and resolve to nothing. `src/index.ts` re-exports
`guardTmpdir` for the server's sake, and the module stays INERT on import: a
consumer typing `import { emitDeck } from "@jokerized/decksmith"` must not have
its `TMPDIR` deleted as a side effect, because an absent `TMPDIR` is inherited by
every child we spawn — puppeteer, ffmpeg, edge-tts.

Two holes were found and closed after the first cut, and each had made the guard
a silent no-op:

- **Both sides of the comparison are realpath'd.** `require.resolve` hands back a
  real path; `$TMPDIR` is whatever the environment wrote. A checkout reached
  through a symlink compared unequal to its own root, so the guard printed
  nothing while the tree kept filling.
- **A non-existent `TMPDIR` resolves to its nearest existing ancestor.**
  `realpathSync` refuses a path that is not on disk, and `os.tmpdir()` never
  asked for one to be. This matters because `src/server/main.ts` does not
  `mkdtemp`: at module load it runs `mkdirSync(work, { recursive: true })`, which
  CREATES the missing parents, so an empty `<repo>/notyet/decksmith-server`
  appeared in the checkout with nothing for `git status` to report about it.

`scripts/tmpdir.mjs` is deleted and `vitest.config.ts` points at
`test/setup-tmpdir.ts`, which runs per worker because `os.tmpdir()` is read at
call time and repointing it in the parent would not reach a forked test.
`.gitignore`'s ten stale scratch prefixes are replaced by two ANCHORED globs,
`/decksmith-*/` and `/ds-*/` — anchored because unanchored they also matched
`src/ds-helper/` and `experiments/ds-svg/`, and a directory `git add -A` skips is
a branch that builds only on the machine that wrote it.

The open-threads handoff's `TMPDIR` paragraph
(`.planning/handoffs/2026-08-02-publishing-and-open-threads.md`) is marked closed
in place and points here and at the source.

## 2. The deck player, hardened

Not the custom element: `<decksmith-player>` and all six steps of
`2026-09-07-player-as-a-module.md`'s build order shipped earlier, in PR #69. What
landed on this branch is the hardening that mapping the element turned up.

- **`refused(err)`** is a pure exported predicate splitting an autoplay refusal
  from a segment the browser cannot play. Unknown rejection names FAIL SAFE to
  "blocked", because names vary by engine and "press any key" over a file we
  could have played still recovers on the first gesture, where the other way
  round leaves a recoverable deck permanently silent. The evidence for the
  `NotSupportedError` side is one run in one headless browser, and the source
  says so rather than generalising it.
- **`flags()` grew a third branch.** A missing segment reads "narration
  unavailable", not "press any key for sound", and it is tested ahead of `muted`
  because it is the one a viewer can do nothing about.
- **`unlock()` retries an unplayable segment as well as a blocked one**, so a
  transient network failure recovers on a gesture. Nothing retries unasked.
- **`dwellMs({playing, heard, gapMs})`** is a pure exported decision, and
  `Voice.onSettled(heard)` is called from both `play()` handlers. `voice.at`
  answers synchronously about whether a segment EXISTS while `play()` rejects a
  beat later, so autoplay now advances on the dwell clock instead of waiting for
  an `ended` that a source which never loaded cannot fire.
- **The dead epoch guard on the `ended` listener is gone.** It read
  `const mine = epoch` and compared `mine === epoch` on the next line, always
  true, on a listener installed once with no per-stop value to close over. The
  comment now names what actually keeps a stale `ended` out: `silence()` drops
  the source and calls `load()`, which aborts without firing it.

Two deliberate NO-CODE-CHANGE decisions, both now recorded at the source rather
than left as open bullets in the design note:

- **No `dispose()`.** The runtime lives in an iframe and
  `DecksmithPlayer.#teardown` removes it, so the frame IS the teardown. Recorded
  at the self-boot with the full listener inventory.
- **No class-name prefixes.** Two players are two iframes with two documents, so
  the chrome classes have nothing to collide with. `.ds-live` is the only
  two-sided name — written by `src/emit/theme.ts`, set by the runtime on the
  composition document — and renaming it is a three-sided change.

And one revert: **a lazy frame reach was tried and taken back** (e530d57). It
latched the iframe's pre-navigation `about:blank` document. `frameOf` is called
exactly once, after `await whenReady(player)`.

The last row was the one to act on, and it is now done. `test/deck-page.test.ts`
serves a built deck over http and drives it in the renderer's own Chrome; it was
proved able to fail against four deliberate regressions, and building it found a

server produced had a timeline that could not load. The first three rows are
still NOT MEASURED and nothing here should be quoted as though they were.

The reasoning that made the row urgent still stands and is worth keeping: no
BUILD GATE opens `deck.html` by construction — `src/verify/index.ts` filters
`DECK_PAGE` out of the composition scan, because the wrapper is a presented page
whose rAF loop legitimately reads a clock. A test is not a gate. It runs on a
deck the suite builds and says nothing about the deck a user ships, so every
change in section 2 still reaches a user unchecked. A gate passing is not
evidence, and neither is a test.
